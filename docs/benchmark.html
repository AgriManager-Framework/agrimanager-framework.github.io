Benchmark

A three-tier generalization ladder that asks how far a policy transfers.

The AgriManager benchmark asks whether a prompt-conditioned LLM-RL policy generalizes across the heterogeneity of agricultural management. It decomposes that question into a three-tier ladder of eight settings, with a shared evaluation protocol, where each tier widens the gap between training and test. Every setting is scored on a frozen held-out test suite with three training seeds per arm.

Each tier changes more of the task interface between training and test.

A fixed-interface neural network cannot run once a shift changes its input layout or action encoding. A prompt-conditioned LLM re-reads the schema each episode.

The three-tier ladder#

  • Tier 1 — Within Schema (distributional shift). The schema is fixed; only the episode context (weather, crop, prices) varies.
  • Tier 2 — Single-Axis Schema. One of the observation Σ_O, action menu Σ_A, or reward formulation Σ_R changes between train and test.
  • Tier 3 — Compositional Schema. Several schema components change at once; the cross-simulator cases also change the dynamics P across DSSAT, WOFOST, and Cycles.

Baselines & references#

The target policy is prompt-conditioned LLM-RL, in think and no-think variants. It is compared against:

  • The untrained model — the same backbone before RL, scored under both response formats on the same test scenarios.
  • Neural-network PPO — Stable-Baselines3 PPO over the numerical observation, with the interaction budget of LLM-RL and its one gradient pass per batch. This fixed-interface network applies to the Tier 1 settings; potato weather-regime adds DQN and A2C, and the action-menu setting adds MaskablePPO over a shared action vocabulary and PPO trained on each test menu.
  • Scripted agronomic reference — a fixed rule set per simulator codified from agronomic guidance, such as crop-stage fertilizer and irrigation rules on WOFOST and a corn–soybean rotation for Cycles crop planning. It is uncalibrated against experts or optimal control and marks codified practice.
  • No-action — the zero-action control; on the fertilizer and irrigation tasks it applies no input, so falling below it is worse than abstaining.

Normalized return#

Normalized return places a policy relative to the two references, both scored on the same scenarios:

normalized return
R̃(π) = ( R(π) − R_no-action ) / | R_ref − R_no-action |

   R̃ = 0  →  matches no-action
   R̃ = ±1 →  matches the scripted agronomic reference
   R̃ > 1  →  exceeds the scripted agronomic reference

The gap R_ref − R_no-action is used as a denominator only where the reference clears no-action by at least a tenth of the think arm's gain over no-action on that target. Where it does not, the benchmark reports the gain over no-action, R(π) − R_no-action. The gap varies across targets, so compare policies by R̃ only within a target. Raw returns, both reference returns and the gap are published for every headline cell (Reproducing the paper).

Known limits of the references#

  • Weather-regime cannot be normalized. On its test splits the scripted reference sits at or below no-action (gap −0.148 to +0.017, below zero on 8 of 10 crop–split targets), so this setting reports the gain over no-action.
  • On WOFOST the reference is a weak "1". The untrained think model already scores above 1 on the WOFOST settings. A normalized score of 5 means five times the gap between no-action and a conservative schedule, with no optimality bound implied.
  • The submitted DSSAT reference values were set by hand. No run or code survives for them. The final numbers use a code reconstruction of the fixed DSSAT schedule, which reproduces the submitted input totals (116 kg/ha N, 264 mm irrigation).
  • The current Cycles reference degenerates to no-action on crop growth. The current ag_heuristic code has no nitrogen rule on the Cycles maize task. The paper uses the first implementation, which reproduces the submitted reference exactly; see Evaluation for how each paper reference is run.
  • The Cycles crop-growth test suites were rebuilt from unused weather years after the first build was found to repeat the validation years; see Held-out test suite.

What the paper finds#

Confirmatory results are the three-seed test-suite results; results only on validation or from a single seed are exploratory. In short, on the Qwen3-4B backbone:

  • Tier 1 (Within Schema). The think policy exceeds neural-network PPO with the same interaction budget and one gradient pass per batch on all three settings (eight-pass PPO, in the appendix, matches it on crop-variety). No-think training stalls near no-action where the reward penalizes input use. On price-regime, think and no-think are level.
  • Tier 2 (Single-Axis Schema). Observation transfer needs decision-critical state: RL training does not help once the resource-state fields are removed. Action-menu results are consistent with joint action-menu coverage. With reasoning, a policy trained on yield alone transfers to unseen objectives, and multi-objective training adds a little.
  • Tier 3 (Compositional Schema). The unified policy learns DSSAT and approaches its specialist there; the per-simulator specialists stay ahead on the WOFOST and Cycles profit targets. Single-source training mostly hurts zero-shot transfer across simulators: four of six transfers score below the untrained model.
  • Reasoning. The think/no-think ordering above holds on the Qwen backbones tested; a single-seed Llama-3.2-3B pair reverses it.

Setup#

LLM-RL trains Qwen3-4B-Instruct with GRPO on VeRL; the neural-network PPO baseline trains Stable-Baselines3 PPO on the numerical observation. The default objective is profit_max (terminal storage-organ yield minus input costs), with per-setting reward overrides. Each arm trains three seeds and is scored at its terminal checkpoint with greedy decoding; see RL training and Evaluation.

Tracking OOD generalization during training#

To watch generalization to held-out conditions live during training, declare several named validation sets along one OOD axis. AgriManager logs a separate curve per set, so an in-distribution id set sits next to each OOD set. These curves are for monitoring and are exploratory; they never select checkpoints. Two steps:

1. At dataset build — set the axis, and mark each held-out split as a validation set with an axis label:

yaml · dataset config
validation_axis: weather_regime          # the OOD axis
sampling:
  splits:
    train:                               # in-distribution training
      role: train
      labels: { weather_regime: id }
    val_id:                              # in-distribution validation
      role: validation
      validation_set: id
      labels: { weather_regime: id }
    val_drought:                         # one held-out regime
      role: validation
      validation_set: drought
      labels: { weather_regime: drought }
    # … val_wet, val_hot, val_cold likewise

2. At train — point data.val_sets at the built parquets and name the axis:

bash · train
bash entrypoints/train/train.sh --config-name agri_grpo \
  data.train_files=<dir>/train.parquet \
  data.val_files=null \
  data.validation_axis=weather_regime \
  +data.val_sets.id=<dir>/val_id.parquet \
  +data.val_sets.drought=<dir>/val_drought.parquet \
  # … +data.val_sets.{wet,hot,cold}=…

Training then logs one generalization curve per set under val-*-weather_regime/<set>/… (with a matching train-* mirror), so you read the in-distribution id set against each held-out regime as training runs. The same two keys work on any axis — action_menu, reward_formulation, or simulator.
