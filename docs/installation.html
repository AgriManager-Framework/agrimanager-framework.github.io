Installation

One script, in a CPU mode or a GPU mode.

Prerequisites#

  • Linux and Python 3.12 (Conda or uv)
  • CUDA 12.8 drivers for training and for scoring language-model checkpoints

Install#

bash
# 1. clone with the VeRL submodule
git clone --recursive https://github.com/AgriManager-Framework/AgriManager.git
cd AgriManager

# 2. a clean Python 3.12 environment (Conda or uv)
conda create -n agrimanager python=3.12 -y && conda activate agrimanager
# or: uv venv --seed -p 3.12 .venv && source .venv/bin/activate

# 3. one of the two modes
bash install.sh --cpu   # WOFOST + Cycles, scripted and NN baselines, tests
bash install.sh --gpu   # adds CUDA 12.8 PyTorch, vLLM and FlashAttention

What install.sh does#

  • Initializes the VeRL submodule (v0.7.0-1, commit 7522bef0) and installs it.
  • Clones the WOFOST-Gym fork (github.com/AgriManager-Framework/WOFOSTGym, commit 1096a6d7) and the CycleGym fork, the Gym wrapper of the Cycles simulator (github.com/AgriManager-Framework/cyclesgym, commit c5f4ba12), into ../AgriManagerExternal/ and installs them. CycleGym's bootstrap downloads the Cycles v0.12.9-alpha binary. Each fork is the upstream wrapper plus one patch commit.
  • Installs pinned Python packages: --cpu uses requirements/cpu.txt with requirements/locks/agrimanager-py312-cpu.lock.txt; --gpu uses requirements/locks/agrimanager-py312-cu128.lock.txt (PyTorch 2.8.0, vLLM 0.11.0, Transformers 4.56.1) and a FlashAttention 2.8.1 wheel.
  • Installs AgriManager in editable mode and checks the imports.

Options: --external-dir DIR clones the wrappers elsewhere (then export WOFOST_GYM_PATH and CYCLES_GYM_PATH); --skip-cycles leaves out CycleGym; AGRI_USE_LOCKFILE=0 lets pip resolve versions, and results may then differ. DSSAT is a separate native build: see DSSAT runtime.

Use a fast file system

On a shared cluster, create the environment on fast storage. On a hard-disk-backed parallel file system we measured install.sh --gpu at 45 minutes and import vllm at about ten minutes; on an NVMe-backed one, ten minutes and four seconds.

Weather data#

WOFOST weather pools download automatically on first use into .cache/wofost_gym/ at the repository root, also when an evaluator scores a suite that needs them. If the repository sits on a small disk, make .cache a symbolic link to a larger one first. Cycles and DSSAT need no download.

Environment variables#

Most users need none of these.

VariablePurpose
WOFOST_GYM_REMOTE, WOFOST_GYM_REFinstall: git remote and commit for WOFOST-Gym (default: the AgriManager-Framework fork at the pinned commit)
CYCLES_GYM_REMOTE, CYCLES_GYM_REFinstall: the same for CycleGym
AGRI_EXTERNAL_DIRinstall: same as --external-dir
VLLM_USE_FLASHINFER_SAMPLERGPU runs: the train and eval entry points set it to 0, so vLLM does not JIT-compile FlashInfer sampling kernels, which needs nvcc on the GPU node. Set 1 to use FlashInfer
WOFOST_GYM_PATH, CYCLES_GYM_PATH, DSSAT_GYM_PATHruntime: simulator locations (Configuration)
HF_TOKENonly to upload checkpoints or result bundles

Check the install#

bash
python -c "import agrimanager, pcse_gym, cyclesgym; print('ok')"
bash smoke_tests/wofost_gym/run_cpu_quickstart.sh
python -m pytest -q tests

Both modes were run on 2026-10-25 from a fresh clone with an empty pip cache: --cpu in about two minutes on a CPU machine, --gpu in about ten minutes on one A40 (NVMe storage). In both, 194 tests passed and the quick start printed the expected numbers. Per-simulator smoke tests are described in smoke_tests/{wofost_gym,cycles_gym,gym_dssat}/README.md.
