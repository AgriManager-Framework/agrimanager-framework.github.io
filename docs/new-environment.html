Adding a new environment

Drop a four-file package into agrimanager/env/ — there is no registry.

Both dataset build and training resolve your environment by folder name — importlib.import_module("agrimanager.env.<env_name>") — and discover your classes automatically. Drop a new folder in, and it works.

The four-file contract#

Create a package at agrimanager/env/<your_env>/ with four files:

FileWhat it provides
env.pysubclass of BaseEnv — reset(), step(action), system_prompt()
env_config.pysubclass of BaseEnvConfig
prompt.pyparse_action_response(text) → Optional[int]
create_dataset.pysubclass of BaseDatasetGenerator plus a module-level generate(config, output_dir)

How an environment plugs in#

Steps#

  1. Maintain the simulator externally under ../AgriManagerExternal/<env>; AgriManager only integrates it.
  2. Create the four-file package in agrimanager/env/<your_env>/, mirroring wofost_gym/.
  3. Export your classes in the package __init__.py's __all__ — this is how discovery finds them.
  4. Stamp env_name into every parquet row's env_config. That is the registration.
  5. Write a dataset config with env_name + dataset_id, then run entrypoints/dataset/build.sh.
  6. (Optional) add nn_adapter.py with a BaseNNEnvAdapter for the neural-network PPO baseline.
  7. Smoke-test it — copy smoke_tests/wofost_gym/, swap the env name, and run the build/train/eval scripts.
Runtime contract

Return a scalar reward every turn. If your env is trajectory-rewarded, emit 0 on early turns and the trajectory reward on the final turn. The action menu rendered in your prompt and parse_action_response() must stay mutually consistent.

Boundary rules

No if env_name == … branches anywhere — dispatch always goes through create_environment(). Never modify verl/ for an env integration. Hand-run tooling (asset generation, baselines, analyses) belongs in integrations/<env>/.
