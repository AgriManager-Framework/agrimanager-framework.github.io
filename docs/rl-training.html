RL training

How training works here, the options you control, and how the paper's runs were set up.

Training is multi-turn GRPO on VeRL, launched with entrypoints/train/train.sh (default config agri_grpo). The policy rolls out a season turn by turn and the trajectory return drives the update — see Framework for the loop and Quick start for the commands. The default config already enables GRPO, the reward-variance filter and per-turn training; the response format (think or no-think) is set per dataset.

One policy across simulators#

The policy is prompt-conditioned: it reads the schema — observations, action menu, objective — from the prompt of each episode. WOFOST, Cycles, and DSSAT all reach it as text, even though their dynamics and interfaces differ, so one policy can train across all of them at once.

Each training instance is a triple (Σ, P, R) — the prompt-declared schema, the simulator dynamics, and the matching reward — sampled from a mixed distribution; training maximizes the expected return over that mixture:

joint objective
J(θ) = E[ R(τ) ]     with   (Σ, P, R) ~ D_train ,   τ ~ π_θ( · | Σ )

The dynamics P never enter the policy — only the prompt schema Σ does — so mixing simulators is just mixing rows in the dataset. The Tier 3 unified policy trains this way across the three simulators. In the paper it learns DSSAT and approaches its DSSAT specialist, while the per-simulator specialists stay ahead on the WOFOST and Cycles profit targets (Benchmark).

Training levers#

Two behaviors are specific to AgriManager. Everything else — the advantage estimator (GRPO by default, stepwise GAE available), model backbone, epochs, and GPUs — is plain training config; see Configuration.

  • Reward-variance filter (on by default) — keeps only the prompt groups with high in-group reward variance and skips uninformative batches (RAGEN-style), so updates focus on rollouts that carry signal. Toggle with trainer.rollout_filter.enable. When every group is filtered out for 5 consecutive steps (max_consecutive_all_filtered_steps), the run stops early; its last checkpoint is its final policy.
  • Think / no-think — in think mode the policy writes a short reasoning block in a <tool_call> tag before its <answer>; in no-think mode it writes the answer alone. Set per dataset with env.require_think. On the Qwen3-4B backbone, no-think training often stalled near no-action where the reward penalizes input use, and several no-think runs stopped early through the filter above. A single-seed Llama-3.2-3B pair reverses the think/no-think ordering, so treat this as a property of the backbone tested.

Neural-network baselines#

entrypoints/train/nn_train.sh --config-name nn trains a Stable-Baselines3 policy on the numeric observation, on a CPU. It is a fixed-interface baseline: its input layout and action head are fixed at training time.

KeyValues
agent.typePPO (default), MaskablePPO, A2C, DQN
